# `instruments/` — the third-party drop-in slot (ADR-010 decision 5)

**Empty by design until WO-019.** This directory exists so the discovery door has a home and the
layout is contract, not ceremony: a handed-in instrument is **a directory of at most five files**,
dropped here (or in the per-user instruments directory) and discovered at launch — no
registration, no config edit, no restart ritual, no intervention.

```
instruments/
└─ my-fm-terrain/
   ├─ sparqmod.toml        # 1 — the manifest (docs/api/manifest-schema.md)
   ├─ fm-terrain.wasm      # 2 — the component; small assets embed in its data section
   ├─ example.sparqpatch   # 3 — the instrument doing its job
   ├─ preview.svg          # 4 — the library-card render, GENERATED by `sparq mod validate`
   └─ README.md            # 5 — what it is, what it needs, licence
```

The rules at the door (all pre-existing contract behaviour, module-api §11): a bad manifest never
loads; one broken package cannot hide the others; every failure is reported verbatim in the module
browser with the file it came from. The sixth file is `E-PACKAGE-FILECOUNT` — bulk assets ride
**by hash** (`state.assets[]`) from the content-addressed library, never as extra files.

**The doors.** `sparq mod list` shows the launch view (what loads, what is refused and why);
`sparq mod validate DIR` runs the hand-in gate (`MODULE-BUILD-GUIDE.md` §7). Authoring starts at
[`MODULE-BUILD-GUIDE.md`](../MODULE-BUILD-GUIDE.md) and the skeleton in
[`reference/instrument-template/`](../reference/instrument-template/) — that template is SOURCE,
not a package: the distributed five files come out of `sparq mod package` (WO-019).

*This README is the folder's own layout artefact — `sparq mod list` exempts it from the
loose-file words. Nothing else belongs at this level: packages live in their own directories.*
